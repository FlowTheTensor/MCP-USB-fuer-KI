LVL 3 · Station 1 · Grundlagen

Die drei Grundbausteine eines Servers

⚙ Tools – Aktoren

Funktionen, die etwas tun oder berechnen: SQL-Abfrage ausführen, Datei anlegen, Mail senden.

gesteuert vom Modell: Das LLM entscheidet, wann es ein Tool braucht.

tools/list · tools/call

▤ Resources – Speicher

Daten zum Lesen, jeweils mit einer Adresse (URI): Dateiinhalt, Datenbankschema, Dokumentation.

gesteuert von der Anwendung: Der Host bzw. der Mensch wählt aus, was als Kontext mitgegeben wird.

resources/list · resources/read

☰ Prompts – Befehlssätze

Vorgefertigte Vorlagen für typische Aufgaben, oft mit Platzhaltern, z. B. „Notenbericht für Klasse ___“.

gesteuert vom Menschen: Er wählt die Vorlage bewusst aus, etwa als Slash-Befehl.

prompts/list · prompts/get

LVL 3 · Station 2 · Grundlagen

Tools entdecken: tools/list

Der Client fragt: „Was kannst du?“ Der Server antwortet mit einer Liste. Jedes Tool hat einen Namen, eine Beschreibung (die liest das LLM!) und ein inputSchema. Das ist ein JSON Schema, das festlegt, welche Parameter erwartet werden.

{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "tools": [
      {
        "name": "query_database",
        "description": "Führt eine SQL SELECT-Abfrage auf der Schul-Datenbank aus.",
        "inputSchema": {
          "type": "object",
          "properties": {
            "query": { "type": "string", "description": "Die SQL SELECT-Abfrage" }
          },
          "required": ["query"]
        }
      }
    ]
  }
}
LVL 3 · Station 3 · Grundlagen

Tools benutzen: tools/call

Anfrage

{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "query_database",
    "arguments": {
      "query": "SELECT vorname, klasse FROM schueler LIMIT 2"
    }
  }
}

Antwort

{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "[{\"vorname\": \"Anna\", \"klasse\": \"5a\"}, {\"vorname\": \"Leon\", \"klasse\": \"5a\"}]"
      }
    ],
    "isError": false
  }
}

Das Ergebnis steckt in result.content, einer Liste von Inhalten. Neben "text" gibt es z. B. auch "image" oder "audio".

Terminal: Sprich direkt mit einem MCP-Server

Hier läuft ein simulierter MCP-Server, der wie der Server aus SQLite-per-MCP funktioniert (mit Beispieldaten). Du bist jetzt der Client. Schicke JSON-RPC-Nachrichten und beobachte die Antworten. Tipp: Beginne mit dem Handshake. Mit Strg+Enter sendest du.

GETRENNT
Aufträge für das Terminal
  1. Schicke tools/list vor dem Handshake. Was passiert?
  2. Führe den kompletten Handshake durch (3 Nachrichten).
  3. Finde heraus, welche Tabellen es gibt und welche Spalten die Tabelle lehrer hat.
  4. Lass dir alle Lehrkräfte mit Fach Informatik anzeigen (WHERE fach1 = 'Informatik').
  5. Versuche, mit DELETE FROM schueler Daten zu löschen. Welche Fehlerart bekommst du?
  6. Erzeuge absichtlich die Fehler -32700, -32601 und -32602.
  7. Was antwortet der Server auf eine Notification?
LVL 3 · Station 5 · Erweiterung

Benachrichtigungen & Gegenrichtung

  • Änderungen melden: Wenn sich die Werkzeugliste ändert, schickt der Server die Notification notifications/tools/list_changed. Der Client fragt dann erneut tools/list ab.
  • Fortschritt: Bei langen Aufgaben kann der Server notifications/progress senden.
  • Abbrechen: Mit notifications/cancelled kann eine laufende Anfrage abgebrochen werden.

Auch der Client kann dem Server Fähigkeiten anbieten, wenn er sie beim Handshake ankündigt:

SamplingDer Server bittet den Host, das LLM etwas formulieren zu lassen. Der Server braucht dann kein eigenes Modell.
RootsDer Host teilt mit, in welchen Ordnern der Server arbeiten darf.
ElicitationDer Server fragt beim Menschen nach einer fehlenden Angabe, z. B. „Für welche Klasse?“
